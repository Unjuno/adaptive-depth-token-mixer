# アーキテクチャ仕様 v0.1

## 採用するもの

共有下位2層と分岐共通KVを持つ、多分岐の因果的生成器。既定は追加2・4・6層の3経路、隠れ幅64、4 heads、FFN幅128、語彙64、最大列長64。分岐は独立した重みと出力Headを持つ。同じ深さの複数分岐も許す。

## 状態の所有権

| 所有者 | 保持する状態 | 更新条件 |
| --- | --- | --- |
| 共有下位層 | 2層それぞれの通常Self-Attention KV | 入力・確定トークンを各1回処理 |
| 共通メモリ生成部 | 最終共有表現から投影したKey/Value | 全トークンで1回生成して追記 |
| 各分岐 | 当該位置の一時的な活性値のみ | 選択時に計算し、履歴KVとして保存しない |
| Router | 現在の共有表現からの選択 | 分岐を実行する前 |

分岐の各ブロックは現在の活性値から独自Queryを作り、同じ共通KVへ因果的にAttentionする。Query投影・出力投影・FFNは分岐固有。全ブロックでKVの形状規約を統一し、履歴のコピーを作らない。

## 必須の実装契約

1. PrefillとDecodeの両方で未来を参照しない。現在位置以前の共有メモリだけを読む。
2. 共通KVへは各トークンについて1回だけ追記し、分岐切替による過去のbackfillを行わない。
3. 推論では先にRouterを実行し、選ばれなかった分岐・Headを実行しない。学習用の全分岐評価は別APIにする。
4. 分岐順序・選択履歴は、同じ確定トークン列に対する共有状態を変えない。異なる生成トークン列を同じ状態と呼ばない。
5. 共有KVの読み出しは非破壊。分岐にin-place書換えを許さない。
6. Softmaxは確率への正規化であり、トークン確定はその後のargmaxまたはsampling。最初の評価はgreedyとする。

## 比較した案と境界

- 独立Self-Attention分岐: 既存モデルから分岐を育てやすいが、トークン切替時に分岐固有KVの欠損を扱う必要がある。今回の本実験には採用しない。
- 共有KV・複数分岐: 今回採用。過去状態を共通化し、計算経路の切替と品質・速度を別々に評価する。
- 全分岐を計算後に出力を選択: 学習ラベル作成やOracle診断には使えても、計算省略の主方式ではない。

共有KVから計算できることは、通常8層モデルとの出力同一性や品質の保証ではない。共有KVの参照構造を選んだことと、その構造が実験で成立したことを区別する。

## 関連分野

表現学習: 複数分岐が利用できる共有表現。計算機システム: キャッシュ所有権と実行省略。統計的意思決定: 品質制約下での経路選択。いずれも本リポジトリでの有効性は未検証。
