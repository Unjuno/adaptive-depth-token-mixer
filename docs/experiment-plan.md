# 共有KV・多分岐の最小実験計画 v0.1

状態: **NOT_IMPLEMENTED / NOT_RUN**。以下は合意した計画であり、結果ではない。
数値の既定値は [minimal.yaml](../configs/minimal.yaml)。実装前に未確定項目を凍結し、変更履歴を残す。

## 目的と対象外

まず3本以上の分岐が共通KVで学習・生成・切替できるかを検査する。成立性と速度改善を分離する。自然言語一般への性能、新規性、既存8層モデルとの出力同一性はこの実験では主張しない。

## 実行順

| 段階 | 操作 | 次へ進む条件 |
| --- | --- | --- |
| 00: 構造 | ランダム重みで逐次KVと全履歴再計算を比較 | 因果性・KV共有・切替・非選択分岐の未実行を全て確認 |
| 01: 深い経路 | 共有2層＋追加6層を次トークン予測で学習 | 開発データの各課題で90%以上正答 |
| 02: 分岐学習 | 共有部・深い経路を固定し、追加2/4層を学習 | 両分岐が未学習例でchanceを上回る。深い側の重み不変を検査 |
| 03: Router | 生成器を固定し、経路選択器だけを学習 | 品質・速度を独立した最終テストで判定 |

## データ

COPY、LOOKUP、TWO-HOPの3課題を使う。各系列に各課題2件、計6件をランダム順で置き、6回答トークンを連続生成する。対応表は系列ごとにランダムな置換とし、固定対応の暗記で済まないようにする。

学習、Router学習、開発、校正、最終テストを**対応表単位**で分離する。同じ表を順序だけ変えて別splitに入れない。データ生成器、split manifest、hash、重複検査を保存する。最終テストは最低1,000独立系列。現在地の設定検査はデータ分離を検証していない。

TWO-HOPが必ず深い分岐を必要とするとは仮定しない。深さ別の性能差がなければ、その事実を報告する。

## 学習

AdamW、初期学習率0.0003、batch 64。深い経路は上限3,000更新、200更新ごとに開発評価。浅い・中間分岐は各上限1,500更新、Routerは上限500更新。checkpoint選択に最終テストを使わない。

分岐学習は正解CEと深い側からのKL蒸留を等重み、温度2で開始する。KL項には温度の二乗補正を適用し、CEは通常温度。教師出力はstop-gradient。共有埋め込み・共有KV投影・深いHeadも凍結対象に含める。

Routerの教師ラベルは専用splitで全分岐を比較し、正答した中で計測コストが最小の分岐とする。全分岐誤答は別記録し、Oracle成功数へ加えない。推論時に正解や全分岐logitsを参照しない。全分岐誤答時のfallback規則は実装前に固定する。

## H / T / D / C / U

| 要素 | 仕様 |
| --- | --- |
| H: 仮説 | 3分岐を再計算なしで切り替えられ、各分岐が学習できる。速度改善は別仮説 |
| T: 最小検証 | FP32・CPU・数学SDPA・2 threads・decode batch 1。1,000切替以上。pilot seed 11、設定凍結後の確認seed 23/37 |
| D: 構造PASS | 全比較でlogits最大絶対差が0.0001以下、未来参照なし、分岐別履歴KVなし、共有メモリの非破壊参照、非選択分岐未実行 |
| D: 品質PASS | 確認seedごとに、深い固定に対する正答率差の対応付き95%区間下限がマイナス2ポイントを上回る |
| D: 速度PASS | 確認seedごとに、深い固定に対するE2E速度倍率の対応付き95%区間下限が1.10を上回る |
| C: 対立仮説 | 共有表現が不十分、全分岐が同能力、Router誤選択、Headや制御費用が支配、生成履歴の誤り累積 |
| U: 不確かさ | seed・対応表・系列内依存・クロック・backend・数値丸め。系列単位の対比較を基本とし、繰返し計時を独立問題として水増ししない |

構造違反はFAIL。品質・速度の区間が境界をまたぐ場合はUNCERTAINとし、点推定だけで成功としない。各確認seedの結果を併記し、pilotを確認結果に混ぜない。3 seedとはpilot 1＋確認2であり、独立確認3回ではない。

主品質指標は回答トークン正答率。各課題別正答率と6回答完全一致率を併記する。自由生成とteacher forcingは別記録。CIは系列を再標本化し、同一対応表内の6回答を独立標本として扱わない。信頼区間の推定法・再標本化回数・停止規則を最終テストを見る前に固定する。標本数の下限は検出力の保証ではない。

## 対照と計時

深い固定、浅い固定、中間固定、循環切替、ランダム選択、学習Router、正解既知Oracleを比較する。Oracleは可能性の診断であり、実運用方式の速度と混同しない。必要に応じ、Routerと同じ経路配分のランダム対照を追加する。

少なくとも30回ウォームアップし、200系列以上・各5反復を交互順で計測する。Prefill、Router、分岐、Head、トークン選択、KV更新を含めたE2Eを主評価とし、Decodeのみは別表。固定長生成を基本とし、早期終了による仕事量差を除く。中央値、分位範囲、対応付きCIを報告する。実測前の速度倍率は記載しない。

## 停止と変更

学習上限で深い経路が各課題90%へ達しない場合は学習不足として止め、Routerへ進まない。分岐の成否と深い教師の成否を混同しない。確認seedの途中結果で条件を調整せず、変更は新しいprotocol versionとして保存する。
